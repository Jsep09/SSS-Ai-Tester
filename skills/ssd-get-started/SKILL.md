# เริ่มใช้ SSD AI Tester

ตอบเป็นภาษาไทยที่ BA/QA เข้าใจง่าย เริ่มด้วย “SSD AI Tester ช่วยวางแผน ทดสอบหน้าจอเสมือนผู้ใช้จริง และสรุปผลพร้อมภาพหลักฐาน” ไม่เริ่มด้วยขั้นตอนเขียนโค้ดหรือติดตั้งสำหรับ developer

## การแนะนำครั้งแรก

1. อ่าน [รายการของชุด](../ssd-skill-list/references/catalog.json) เพื่อแสดงตารางชื่อ Skill / ทำอะไร / ใช้เมื่อไหร่ พร้อมตัวอย่าง `$ชื่อ-skill` อ่าน `SKILL.md` ของ Skill ที่จะแนะนำเพื่อยืนยันว่ามีไฟล์อยู่จริง ถ้า helper ใช้ได้ ให้เรียก `node "<absolute sibling path>/ssd-skill-list/scripts/catalog.mjs"` เพื่อดูรายการและไฟล์ที่มี ไม่อ้างว่าไฟล์เหล่านี้ถูกโหลดเข้าทุกแชตแล้ว
2. แนะนำเส้นทางสั้น ๆ: `plan` ออกแบบกรณี → `script` อ่าน source/Repomix แล้วสร้างสคริปต์ → `run-script` รัน Playwright ตามขอบเขต → `report` สรุปผล เป็นโหมดของ `$ssd-ai-tester` ไม่ใช่ Skill แยก ถ้ามีสคริปต์แล้วให้ตรวจ context และรันโดยไม่ให้ AI กดทุก element สำรวจเว็บเฉพาะเมื่อไม่มี code หรือข้อมูลไม่พอ หากได้รับ Repomix ใหม่ให้ลงทะเบียน อ่านผลกระทบ และ review ก่อนรัน
3. บอกข้อมูลที่ต้องเตรียม: URL และสภาพแวดล้อม เช่น UAT, งานที่อยากตรวจ, ผลที่คาดหวัง/requirement และ session ที่เข้าใช้งานได้ ไม่ขอรหัสผ่านหรือ OTP ในแชต
4. บอกสิ่งที่จะได้รับ: แผนทดสอบ, ภาพหลักฐาน, รายงาน HTML ภาษาไทยที่ส่งต่อไฟล์เดียวได้, Markdown และ JSON โดยแยกผ่าน/ไม่ผ่าน/ทดสอบไม่ได้/ข้าม/ยังไม่ได้ทดสอบ
5. เสนอตัวอย่างเดียวที่ตรงกับงานผู้ใช้ ถ้ายังไม่มีงาน ให้ตัวอย่าง `$ssd-ai-tester plan ออกแบบกรณีทดสอบการค้นหาคำขอจาก requirement นี้` และถามเฉพาะ URL กับงานที่อยากตรวจเมื่อจำเป็น

ตัว Skill สำหรับแนะนำไม่ต้องเปิดเว็บหรือบันทึกข้อมูลทดสอบ หากผู้ใช้สั่งให้เริ่มวางแผนหรือทดสอบไว้แล้ว ให้โหลด [ssd-ai-tester](../ssd-ai-tester/SKILL.md) แล้วทำงานต่อภายในขอบเขตที่ได้รับอนุญาต โดยไม่บังคับผ่านบทแนะนำซ้ำ

## ถ้าพร้อมใช้งานหรือไม่พร้อม

ตัวติดตั้ง ZIP เตรียม Playwright กับ Chromium ให้ครั้งแรกผ่านอินเทอร์เน็ต โดยติดตั้ง runtime กลางแล้วใช้ร่วมหลาย workspace ตรวจ runtime ด้วย helper ของ Skill ก่อนบอกว่าพร้อม ให้ Codex เลือก workspace จากโฟลเดอร์งาน/path ที่ผู้ใช้ให้ ไม่บังคับ path เดียวทั่วเครื่อง ถ้ามีสคริปต์พร้อมแล้ว Browser Use ไม่จำเป็นต่อการรัน

Browser Use ใช้สำรวจเส้นทางใหม่และตรวจปัญหา ต้องมีในแชตแยก ไม่รวมใน ZIP หากไม่มีห้าม fallback ไปยึดเมาส์/คีย์บอร์ด desktop built-in browser มี session แยกจึงอาจต้อง login ใหม่ ส่วน extension ใช้ profile ที่อนุญาตและควรมีแท็บทดสอบเฉพาะ

หากผู้ใช้ต้องทดสอบ native desktop ด้วย Computer Use บน Windows ให้บอกว่าใช้ foreground; ถ้าต้องทำงานอื่นพร้อมกันให้ใช้ VM/เครื่องทดสอบเฉพาะที่เตรียมไว้ โหมดแท็บไม่ได้รับรองทำงานต่อเมื่อปิด Codex หรือเครื่อง sleep/lock

เรียก Skill โดยพิมพ์ `$ssd-get-started`, `$ssd-skill-list` หรือ `$ssd-ai-tester` และเลือกจากเมนู Skills ที่แอปรองรับ หากไม่ปรากฏให้เปิด Codex ใหม่ ไม่รับรอง custom slash command ที่ยังไม่ได้ลงทะเบียน
