# Telesale UAT: สร้างหลีดและใบคำขอด้วยบอท

เปิด run-bot.cmd หรือ `node .\run-e2e.mjs` บอทเปิด Chromium ให้ Login เอง แล้วทำงานต่ออัตโนมัติ

## Config สำหรับ BA/QA

แก้ไฟล์ bot.config.json แยกจากสคริปต์:

```json
{ "headless": false, "slowMo": 0 }
```

- headless=false: เปิดหน้าต่างให้เห็นการทำงาน / true: รันแบบซ่อนหน้าต่าง
- slowMo: หน่วงต่อ action หน่วยมิลลิวินาที (0 = ไม่หน่วง, 350 = ดูการคลิกง่ายขึ้น)
- `--headed` หรือ run-visible-bot.cmd บังคับเปิดหน้าต่าง; `--headless` บังคับซ่อนหน้าต่าง โดยยังใช้ slowMo จากไฟล์
- `--reuse-login` ใช้ session เดิมถ้ายังไม่หมดอายุ; ปกติรอผู้ใช้ Login เอง ไม่ใส่รหัสผ่านใน config

สิ่งที่บอททำ

1. ตรวจเอกสารและข้อมูลก่อนสร้างรายการ
2. สร้างหลีดชื่อทดสอบเฉพาะรอบ ใช้โทรศัพท์ `0000000000`
3. คัดลอก PH Application `8100002` เป็นใบคำขอในหลีดใหม่ เลือก `503-Silver`, รายเดือน, เงินสด
4. บันทึกผู้เอาประกัน ผู้รับผลประโยชน์ 100% ผู้ติดต่อฉุกเฉิน และแถลงสุขภาพของข้อมูล UAT
5. แนบเอกสารทดสอบ 3 ประเภท แล้วโหลดหน้าใหม่และตรวจข้อมูลที่บันทึก

รอบนี้จบที่สร้างใบคำขอและแนบเอกสาร ไม่ส่ง QC หรือเปิดกรมธรรม์ การสร้างแต่ละรอบที่สำเร็จแล้วจะสร้างหลีดใหม่ในรอบถัดไป

## แก้ข้อมูล

ข้อมูลเฉพาะเครื่องให้เก็บใน `test-data/scenario.local.json` (รูปแบบเดียวกับ scenario.json) ระบบจะใช้ไฟล์นี้ก่อน และไม่รวมใน Git/ZIP หากไม่มีจะใช้ scenario.json ซึ่งเป็นข้อมูลตัวอย่าง

แก้ `test-data/scenario.json` สำหรับ Application แผน ชื่อทดสอบ เบอร์โทร และ path เอกสาร หรือกำหนด `E2E_UPLOAD_FILE` เป็น path PDF/PNG/JPG/JPEG ของคุณ เอกสารต้องไม่เกิน 20 MB

ไฟล์ต้นฉบับอ้าง path ของอีกเครื่อง จึงเตรียม `test-data/e2e-upload.png` เป็นภาพที่เขียนว่า E2E TEST DOCUMENT / UAT ONLY ใช้ไฟล์เดียวกันกับทั้ง 3 ประเภทตามรูปแบบเดิม ไม่ใช่เอกสารบุคคลจริง เบอร์โทร 11 หลักในต้นฉบับปรับเป็นค่าตัวเลข 10 หลักให้ตรงผลของช่อง masked input

คำตอบแถลงสุขภาพเป็นค่าเชิงลบของ fixture ทดสอบเท่านั้น สคริปต์ตรวจทุกตัวเลือกที่แสดงจริง รวมคำถามที่เพิ่มจากสคริปต์เดิม ห้ามนำชุดข้อมูลนี้ไปใช้แทนคำตอบของบุคคลจริง

ฟอร์มผู้เอาประกันปัจจุบันมี HTML pattern `[A-Z0-9]*` ในช่องชื่อ/นามสกุล ชื่อภาษาไทยที่คัดลอกจาก Application จึงติด validation (รายละเอียดใน `requirements/known-ui-limitation.md`) หากใช้ข้อมูลจำลองที่เป็นตัวพิมพ์ใหญ่ ให้เพิ่มค่าใน scenario ดังนี้:

```json
"insuredNameOverride": { "firstName": "E2E", "lastName": "TEST" }
```

ตัวเลือกนี้เปลี่ยนเฉพาะผู้เอาประกันในใบคำขอทดสอบใหม่ ไม่แก้ Application ต้นทาง และผลทดสอบด้วยตัวเลือกนี้ไม่ครอบคลุมการบันทึกชื่อภาษาไทย

ค่าปัจจุบันเปิดใช้ชื่อจำลอง E2E TEST ตามที่ผู้ใช้เลือกแล้ว สคริปต์ใช้ตัวเลือก “ตามบัตรประชาชน” สำหรับที่อยู่ทำงานและที่อยู่ติดต่อ เพื่อให้ข้อมูลบังคับครบก่อนบันทึก

## รันต่อเมื่อหยุดกลางทาง

`.ssd/progress.json` บันทึกหลีด ใบคำขอ และส่วนที่บันทึกสำเร็จ รอบที่ไม่จบจะใช้รายการเดิมต่อ ไม่กดสร้างซ้ำอัตโนมัติเมื่อไม่แน่ใจว่าการส่งสำเร็จหรือไม่ หาก checkpoint บอกว่าเคยส่งสร้างแล้วแต่ค้นหาไม่พบ ให้ตรวจข้อมูลใน UAT ก่อนแก้ checkpoint

เมื่อ session ยังใช้ได้และต้องการรันต่อโดยไม่ Login ซ้ำ:

```powershell
node .\run-e2e.mjs --reuse-login
```

หาก session หมดอายุ ให้ใช้คำสั่งปกติแล้ว Login ใหม่ เก็บ session ใน `playwright/.auth/` เฉพาะเครื่อง โฟลเดอร์นี้ถูก ignore และไม่ใช่ส่วนของรายงาน ห้ามส่งต่อไฟล์ session หรือ trace โดยไม่ตรวจข้อมูลก่อน

## ผลลัพธ์

แต่ละรอบอยู่ใน `runs/<รอบ>/` มี `report.html` ภาษาไทยพร้อมภาพฝัง, `report.md`, `report.json`, `results.json`, `screenshots/`, Playwright HTML และ trace เมื่อมีข้อผิดพลาด อ่านรายงานธุรกิจร่วมกับผล process ไม่ถือว่า exit code 0 เพียงอย่างเดียวเป็นการรับรองจาก BA/QA

ใช้ Playwright/Chromium ที่ติดตั้งโดย SSD AI Tester เครื่องนี้ ไม่ต้อง npm install ในแต่ละ workspace หากย้ายตำแหน่ง Skill ให้กำหนด `SSD_TESTER_SKILL` แล้ว bind `fixtures.mjs` ใหม่ด้วย helper ของ Skill
